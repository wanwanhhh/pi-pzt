## 目标型号

E53.D1S-H。USB 接口，Windows 下由系统识别为 CDC 串口
（`USB\VID_0483&PID_0002`，实测 `COM7`，显示为「USB 串行设备」），
走系统自带 `usbser.sys`，**不需要厂家驱动**。

## 接入方式

**pyserial 直连，不用厂家 DLL。**

`protocol/` 已给出完整帧格式，`XMT_DLL_SER.dll` 只是同一套串口协议的 C 封装，用了省不下什么。
对上面那个安装包实查的结论：

- 全包**只有 Debug 构建**。`XMT_DLL_SER.dll` 导入 `mfc140ud` / `VCRUNTIME140D` / `ucrtbased`，
  本机没有 x64 debug CRT，**`LoadLibrary` 直接失败**，包内也找不到 Release 版。
- 唯一能加载的是 11.6 MB 静态 debug 版（x64 各变体字节相同）。Debug 版会 ASSERT/abort，
  不能进无人值守的后端进程。
- 收数据路径依赖 `EntryXMT(..., HWND)` 投递窗口消息，要额外挂一个窗口消息泵。
- 199 个导出，错误码是 DLL 的而不是设备的；字节层被封装后无法单测。

它唯一能省的是组帧与编解码 —— 而那部分已按官方样例逐字节验证（见「协议速查」）。
另两条路也已排除：`DoTextXmtUsbDll.ocx/.tlb`（2021 年前产品才有）、`XMT_DLL_NET.dll`（本机只有 USB 与 RS-232/422，没有网口）。
厂家上位机 `XMTControlComb_20240910 1.6V.msi` 留在包里，只当字节级对照的 oracle。

## 协议速查

### 帧格式

帧格式：

    AA | 地址 | 包长 | B3 | B4 | 数据段(B5…) | BCC

- 地址 `0` = 广播，`1~255` 为下位机地址
- 包长 = 从起始字节**到校验字节**的总长度，即 `数据段长 + 6`（帧头 2 + 包长自身 + B3 + B4 + 校验）
- BCC = 从 B0 到数据段末尾逐字节 XOR（`校验位说明.txt` + `读取电压.txt` 的
  `for(i=0;i<bao_long-1;i++)` 一致）
- 串口参数 115200 8N1（`SendData.py`；也可用 B3=`63` 设置波特率）

### 数值编码

数值编码（`译码以及编码过程…txt`）：

    数值 = ((kk0 & 0x7F) << 8 | kk1) + (kk2 << 8 | kk3) * 1e-4
    负数：kk0 |= 0x80

即**符号 + 幅值**，不是补码；分辨率固定 1e-4，幅值上限 32767.9999。
闭环时单位由指令 `53` 决定：0 mrad / 1 位移 / 2 角秒 / 3 微弧度 / 4 毫米 / 5 纳米 / 6 周期。

### 时序与应答

- **帧间隔最少 50 ms**（协议 §2.5）。管的是**主机下发的指令帧**，即主机侧上限 20 帧/s。
  真机上不强制，见下「本机实测」。生产端仍按手册来。
- **上一条指令未返回前，后续指令不执行** —— 是丢弃，不是排队。
  真机上流运行中可以插命令，见下「本机实测」。
- **读数不占这 20 帧/s 的额度**：`8` 一帧启动后，下位机按 `[6]发送周期(ms)`（正文表给的取值范围是 1~255）
  持续回包，直到 `11` 停止。所以采样率不受 50 ms 限制，**被限住的只有「下发目标」**。
  能跑到几毫秒只影响**表征**（看超调、振铃、蠕变），不影响生产判据 —— 见下一条。
- **判「稳没稳」不能用均匀网格采样。** 固定 50 ms 就是 20 Hz 均匀网格：闭环若在 20 Hz 的整数倍
  附近振荡，采样点每次都落在几乎同一相位上，连续 N 次读数会看起来纹丝不动，而台子其实在振。
  盲区很窄（只在各次谐波两侧一条，宽度取决于窗口长度与判据阈值），落进去的概率不高，
  **但后果是静默错误**：图糊了却记成「已停稳」。而振荡频率会随温度、负载、面板电位器缓慢漂移，
  长时间扫描总会撞上几处。**鲁棒性来自间隔抖动与窗口长度，不来自采样率** ——
  提高采样率根本不解这个问题，打散间隔才解。`tools/xmt_check.py` 的轮询已加 0~15 ms 抖动。
- **写指令没有应答**：指令表里 `0 单路电压` / `1 单路位移` 的「下位机」三列全空，读指令（`5`/`6`/`7`/`8`）才有回包。
  也就是说**目标没生效是静默的**，必须靠 `6` 读回校验，不能假设发出去就动了。

### 常用指令（B3）

| B3 | 功能 | 说明 |
|---|---|---|
| 1 | 单路位移 | 闭环设点，整包 11：`[5]通道 [6..9]位移` |
| 0 | 单路电压 | 开环；本仓库只做闭环，不用 |
| 6 | 读单路位移 | 发 7 字节，下位机回 11 |
| 8 | 实时读单路位移 | 带周期(ms)，下位机周期回包 → 可直接喂 SSE 遥测 |
| 11 | 停止实时读数据 | |
| 18 / 19 | 开闭环 设置 / 读取 | |
| 26 / 27、34 / 35 | 位移高限 / 低限 标定与读取 | 软限位的权威来源 |
| 32 / 33 | 系统电压高限 | |
| 53 | 读取下位机单位 | 解决 µm / mrad 歧义 |
| 77 | 通信连接是否正常 | 回 `[5]'O' [6]'K'`，可当心跳 |
| 78 | 读取下位机型号 | 回 `[5]` 机型码 |
| 108 / 109 / 110 | 外部触发位置 设定 / 读取 / 开关 | CCD 触发联动 |
| 61 / 62 | 多通道同步输出、同步触发 | |

例：读型号（纯查询，无数据段，不产生任何运动）

    AA 01 06 4E 00 E3        # BCC = AA^01^06^4E^00 = E3，回包 [5] 为机型码

## 本机实测（与手册的差异）

用 `tools/` 下这几个脚本量的：`xmt_check.py`（只读自检）、`xmt_wave.py`（静止波形）、
`xmt_scale.py`（单位尺度）、`xmt_move.py`（运动）。

### 单位关系 —— 最大的坑

| 量 | 指令 | 单位 |
|---|---|---|
| 设点 | `1` | **µm** |
| 读回 | `6` / `8` | **4/3 µm**（×0.75 才是 µm） |
| 行程上下限 | `27` / `35` | **µm** |

`53` 返回 `1`「位移」，**不含尺度**，手册全书也没写这个系数。

**把读回值直接当设点写回去，台子会跑偏 4/3 倍。** 实测定量：当时读回 144.8785，把它原样当设点
写回去，读回随后变成 **193.2605** —— 折算成真实位置是从 108.66 µm 走到 144.95 µm，多走 36.3 µm，
而本意是零位移。链路上的两个读回值都是量到的；108.66 与 144.95 是 ×0.75 折出来的。

判别法（两条独立证据）：

1. `xmt_scale.py`（在 `tools/`）把设点抬高 1/2/4 µm，量得 Δ读回/Δ设点 = 1.331（4/3 = 1.333）。
2. 反证：若 `27/35` 是读回单位，高限 201.1799 只等于 150.885 µm，在它上方下发会被夹取，
   而**夹取后的读回恰好等于 27 的原始值 201.1799** —— 换算来回是恒等，与 0.75 精不精确无关。
   实测下发 152 µm，读回 **202.657**，比 201.1799 高 1.48 读回单位（约 1.11 µm），远大于
   ±0.045 µm 的定位误差；同时 152/0.75 = 202.667，实测与它只差 0.007 µm。
   既没被夹、又确实走到了 152 µm 附近 → `27/35` 本来就是 µm。

   （第 2 条当时是用一段一次性探针脚本跑的，脚本没入库；判别链如上，要复核照做即可。）

## 已知缺口与注意点

- **超出范围由控制器自行夹取。** 上位机说明书写明：「输入数据应在开环电压范围内，闭环数据在
  行程范围内，否则超出部分在开环下按照最大电压或最小电压输出、闭环下按最大或最小行程输出。」
  与 AGENTS.md 记录的 PI 侧行为一致 —— 后端仍必须自己夹取，不能依赖它。
- **数值含义随开闭环变化。** `1.000` 在开环是 1 V，在闭环是 1 个当前单位（µm / mrad / 角秒…），
  与原始 DA 值不是一回事。发送前必须先确认 `19`（读开闭环）与 `53`（读单位）。
- 厂家上位机的做法是「**通过读开闭环来统一上位机与下位机的开闭环关系**」，不本地记状态 ——
  和 AGENTS.md「前端不做本地权威状态」一致。
- 协议表里**没有**「停止运动」和「释放/关伺服」指令。闭环位移是设点后守位，没有轨迹可停；
  最接近的只有 `18 开闭环` 和 `72 点单步进的暂停/停止`（仅步进模式）。
  AGENTS.md 里「停止 = 保持不动」「释放 = 关伺服」的语义需要重新定义。
- **关机规程（厂商要求）**：关控制器电源前必须先把输出电压清零，闭环状态要切回开环。
  本仓库「只做闭环、不提供开环」的约束需要为这条留出口。
- 带电禁止插拔输入线、输出线、传感器电缆。
- `78` 的机型码表里**没有** E53.D1S-H（表止于 `0x17 E80.D3S-O`），实际返回码待实测。
- `SendData.py` 里的 `A4 03 08 23 D2` 五字节帧不在指令表中，属其他产品/老协议残留，忽略。
