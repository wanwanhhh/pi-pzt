# 相机设计

**状态**：成形。
**一句话：这份讲相机这一层对外承诺什么 —— 两种会话（预览连续出帧、扫描一次触发一帧）、一套设置、一种数据（原生全幅 16 位），界面看到的一切都是它的派生。** 词在 [词表](../词表.md)；需求在上游（[需求](../需求.md)）；扫描怎么用相机见 [扫描](扫描.md)，图怎么入库与取数见 [数据](数据.md)。

## 这份设计认领了哪几条需求

| 需求 | 这一层给出的回答 |
| --- | --- |
| 「相机仅 Windows」 | 走厂家 SDK 的本地包装，不做第二条通路 |
| 「曝光与增益」 | 曝光预览与采图共用一个值、随时可改；增益恒 0，改增益的接口一律拒绝 |
| 「保存的帧是原生数据」 | 原生全幅、16 位灰度、不裁剪、不拉伸、不伪彩 |
| 「图自己带着参数与亮心」 | `ExposureUs` 与 `CentroidPx` 写进 PNG 的 tEXt；老图没有就写「未记录」 |
| 「一台相机一套设置、两种会话」 | 会话出生时写一次原生全幅 + 曝光 + 增益 0 并读回；预览用连续会话、扫描用一次触发一帧的会话；一个会话最多 arm 一次 |
| 「质心十字线」 | 质心在原生帧上算，口径是整幅强度加权重心，坐标永远是传感器坐标 |
| 「朝向只转预览」 | 朝向是显示参数；90° 整数倍按精确置换，不重采样 |
| 「预览上点图看剖面」 | 整行整列两条全长剖面，取自原生 16 位帧，原值上图 |
| 「饱和要标出来」 | 按实测满量程判饱和，峰值到顶就在界面上标出来 |
| 「80% 能量圆」 | 原始帧上按整幅质心算窗口内 80% 能量圆；不扣背景；饱和 / 半径贴到窗口边 / 圆出画面 / 背景不弱时如实说 |
| 「图库」 | 只列手动保存的帧（按登记表）；改名就是真改磁盘文件名 |
| 「掉线只能手动重开」 | 一个手动按钮；重开 = 重建整个会话；不做自动重连 |
| 「相机状态由后端派生」 | 状态只有六种，界面照着写，不自己记「用户想要预览吗」 |
| 「设备不可用时不冒充」 | 没有会话就没有帧；掉线后不拿上一帧冒充实时画面 |
| 「相机与位移台互斥」 | 扫描进行中一律 409；开始扫描时后端把预览会话换成扫描会话（预览意图保留，结束后按需重建） |
| 「扫描中相机出错即整条失败」 | 相机报错不重试、不跳过、不自动清理半截扫描；**触发没出帧补发一次**，补了还没有帧才失败 |

## 一、两种会话、一套设置

承诺：会话建立时把设置写一次并读回：原生全幅、同一个曝光、增益 0。预览与手动保存用同一条连续出帧的会话；扫描用另一条**一次触发一帧**的会话，arm 之后不预触发 —— 每一帧都由扫描在到位之后自己触发。一个会话最多 arm 一次，设置出生时写完就不再动；扫描接手与交还时按目标模式重建会话，不原地改。

出什么事会说什么：要改增益 → 422 明说本机恒为 0；要同时开第二条会话 / 中途重新 arm → 拒绝；要改 ROI → 拒绝（预览看到的就是存下来的那一幅）。

## 二、曝光

承诺：曝光随时可改，流不停；预览和采图用的是同一个值；每一帧保存时把相机读回的实际曝光写进 `ExposureUs`。

出什么事会说什么：曝光写失败 → 返回错误码，不假装成功；老图没有 `ExposureUs` → 界面上写「未记录」。

## 三、预览

承诺：预览给出 JPEG 帧（质量与帧率可设）与一份质心读数；掉线后没有帧。

出什么事会说什么：没有会话 → 预览接口 503 并说清状态；掉线 → 状态变「掉线待重开」，不返回上一帧。

## 四、质心

承诺：质心 = 整幅图的强度加权重心（不扣背景、不设阈值、不开窗），在原生 16 位帧上算完再下发；读数是传感器坐标，与保存的 PNG 同一套，不受预览朝向影响。

出什么事会说什么：光斑小、背景占比大时，质心会被背景拉向整幅重心 —— 这是口径本身，界面不修正。

## 五、朝向

承诺：0/90/180/270 只转预览。90° 整数倍是精确置换，不重采样、不插值。

出什么事会说什么：朝向不对时，保存的文件与质心都不变 —— 界面上的十字线由前端按朝向换算，那是显示不是计算。

## 六、剖面

承诺：点预览上任意一处，给过该点的整行与整列两条全长剖面，取自原生 16 位帧，原值上图；坐标按当前朝向换算成显示坐标。

出什么事会说什么：点在图外 → 直接拒绝，不夹取、不给空值。

## 七、手动保存与图库

承诺：手动保存的帧是原生全幅 16 位 PNG，`ExposureUs` 与 `CentroidPx` 一起写进去；图库按登记表列（不靠文件名前缀猜）；改名、删除、清空都真的动磁盘，库记录同步变。

出什么事会说什么：改名撞上已有的名字 → 拒绝并回滚；老图缺 tEXt → 图库里写「未记录」，不猜。

## 八、饱和

承诺：饱和门限用实测满量程；帧里到顶的像素数在预览与采图上都给出来。

出什么事会说什么：拿错门限会把过曝判成没过曝 —— 所以门限只有一处（设备文档里的实测值）。

## 九、掉线与会话重建

承诺：掉线后状态落到「掉线待重开」，一切取帧接口拒绝；重开就是整条会话重建（句柄与 SDK 实例一起换），不是只换句柄。

出什么事会说什么：重建失败 → 说来的是哪一类错（缺 DLL / 被占用 / 没枚举到设备），不回落到上一帧。

## 十、与扫描的关系

承诺：扫描接手时把预览会话换成单帧触发的扫描会话（设置写一次、arm 一次、不预触发）；扫描结束后丢掉它，预览要着就按连续模式重建。扫描进行中相机接口一律 409。**某一发触发没出帧**（等帧超过相机帧时间的 2 倍加 0.5 秒、至少 1 秒）时，相机层补发**一发**触发再等一次，并把可能多出来的帧排空 —— 一点一帧不破，这一帧照常入库。

出什么事会说什么：相机报错 → 扫描就地失败；补发后仍无帧 → 这一点没采到，整条失败；跑过的点照实留下，半截扫描由人删；扫描会话建不起来 → 扫描不开始，如实报错。丢触发补发过这件事写进后端日志（第几点、等了多少秒）。

## 十一、80% 能量圆

承诺：打开「80% 能量圆」时，在原始 16 位帧上算出一个以整幅质心为圆心的圆，圆内包含窗口内 80% 的总能量；直径按传感器像素下发。**不扣背景**；窗口只限制积分范围（窗口外不参与），不改变像素。只读最近一帧快照，不额外取帧、不动预览流。

出什么事会说什么：没有帧 → 503；背景占窗口总能量 5%～20% → 照画并标「仅供参考」；超过 20%（80% 圆会圈住背景）、80% 半径贴到窗口边、80% 圆出了画面、光斑小于 1 像素 → 200 + ok=false 说明原因；**窗口被画面裁掉不算贴边**（光斑小又靠边时窗口一定有一边被裁，那只是积分范围到头）；饱和像素数照报，界面也标「仅供参考」；扫描中一律 409。
