# 服务设计

**状态**：成形。
**一句话：这份讲后端服务对外承诺什么 —— 听在哪、什么情况回什么码、界面不在时还跑不跑。** 词在 [词表](../词表.md)；需求在上游（[需求](../需求.md)）；各层内部的承诺见 [设备层](设备层.md) / [扫描](扫描.md) / [相机](相机.md) / [数据](数据.md)。

## 这份设计认领了哪几条需求

| 需求 | 这一层给出的回答 |
| --- | --- |
| 「单人单机、只监听本机」 | 只听 127.0.0.1、单进程；不登录、不多 worker |
| 「后端负责控制」 | 所有判断都在这一侧；界面只是它的一个客户端 |
| 「拒绝永远在后端」 | 拒绝有固定的码：参数 400、占用 409、设备不在 503 |
| 「前端不维护意图」 | 状态只有一个来源：后端推的那一份 |
| 「进硬件前必校验」 | 进硬件前的校验、夹取、错误码检查是安全边界，一处都不省 |

## 一、听在哪

承诺：只听本机回环、单进程跑；界面是同一进程发出的静态文件。

出什么事会说什么：端口被占 → 启动就报错说清，不自己换个端口悄悄起来。

## 二、拒绝的码

承诺：参数不对回 400；设备没连上回 503；设备正被扫描占着回 409；设备层抛的错按同一套映射回出去，不变成裸的 500。

出什么事会说什么：同一个动作在界面上被点、被脚本直接调，回的都是同一个码 —— 拒绝不看是谁在问。

## 三、状态与推送

承诺：状态与遥测走一条单向推送；心跳只表示界面还在，不参与任何扫描的生死。

出什么事会说什么：推送断了 → 界面显示失联，但扫描照跑。

## 四、界面与任务的关系

承诺：界面被关掉、被绕过、被篡改，都不影响正在跑的扫描，也不影响设备的拒绝逻辑。

出什么事会说什么：前端要到了一份它不该做的动作 → 后端拒，前端照抄那句话。
